# 交付评分表

机器项由 `scripts/check_eval.py` 执行，必须全过；人工项由 reviewer 逐条勾选并把证据写在交付里。机器项只覆盖结构，不覆盖创意与可拍性。

## 机器项（脚本判定）

| 检查 | 规则 | 违反后果 |
| --- | --- | --- |
| 分镜表列 | 必须包含镜号、时间码、时长、景别、画面、台词、音效、卖点、素材来源、参考资产、生成要点、风险 | 生成端无法开工 |
| 时间码 | 形如 `0.0–2.0`，首尾相接，不得跳空或倒序 | 剪辑与生成档位对不上 |
| 单镜时长 | ≤5s，按生成工具的 5s 网格拆镜 | 只能靠拉长单镜凑时长 |
| 素材来源 | 只能是 AI、实拍、图库 | 转化镜与质地特写会被误交给 AI |
| 参考资产 | 留空或 CH/SC/PD 两位编号 | 跨镜一致性无法执行 |
| 台词长度 | ≤12 字（字幕行除外） | 主角变辩论赛，爽点被稀释 |
| 必填单元格 | 画面、台词、生成要点、风险不得为空 | 无法复现或无法评估崩点 |
| 机制数字 | 机制 beat 里必须出现具体数字 | 机制等于没有机制 |
| 变量矩阵 | 首行标基线；基线行开启新的对照链；同一链内每行相对上一行只允许一列不同 | 结论不可归因 |
| 原型合法性 | 矩阵与交付里作为主原型出现的只能是 P1–P8、P11 | 组件被当成方向，测的是运气 |
| 交付形态 | 用例声明的节必须出现；要求分镜就必须有，禁止分镜就必须没有 | 交付跑偏 |

## 人工项（reviewer 判定）

- 施压者不是主角；主角台词 ≤2 句（仅 P1–P5、P11）。
- 反转来自旁观者或第三方，不来自主角自夸。
- 爽点一句话里含产品，不是"她真好看"。
- 场景能看见痛点，前后对比同机位同光线。
- 无 AI 承担真实质地细节；无 AI 生成中文文字。
- 功效、时长、价格锚点有用户提供或 commerce claim 结论支撑；示例数字未被当宣称使用。
- 无未授权明星肖像、IP 形象或联名暗示。
- P6–P8 已按 SKILL.md 的等价硬约束核对。

## 判定

- 机器项任一失败：交付不合格，不进投放。
- 人工项失败：写清是创意假设问题还是执行缺陷，再决定改哪一层。
- 结论分三档：可投产 / 需修执行 / 需改假设，不要只写"再优化"。
