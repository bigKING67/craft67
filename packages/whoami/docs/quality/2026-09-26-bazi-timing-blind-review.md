# 八字岁运疑难字样盲审包验收

日期：2026-09-26。目标：把三个句法可疑或版本敏感的扫描读法交给独立审读者复核，同时用两个清晰锚点校准审读质量，避免候选答案、版本信息、上下文通顺度和他人意见先污染判断。

## 交付与分发边界

- 审读者只收到[盲审目录](../research/bazi-timing-blind-review/README.md)，其中包含五张匿名图、[机器任务单](../research/bazi-timing-blind-review/packet.json)和[回答模板](../research/bazi-timing-blind-review/response-template.json)。
- 协调人单独保管[答案键](2026-09-26-bazi-timing-blind-review-key.json)。答案键记录真实锚点、见证、页码、参考字样、案例角色、原始证据哈希、派生图哈希和裁切坐标。
- 协调人使用[裁决核心](../../src/blind-review-adjudication.ts)和[命令行入口](../../scripts/adjudicate-bazi-timing-blind-review.ts)回收两至三份答卷；输出绑定答案键与每份答卷的 SHA-256，不覆盖已有结果文件。
- 源隐藏依赖分发纪律，不是密码学隔离。审读者若能浏览完整仓库，可从其他文档反查来源；实际发送时必须只复制盲审目录。
- 当前只完成可执行的评审材料，没有声称已经取得外部专家意见或改写既有校本。

## 案例设计

盲审包共五例：三个目标案例与两个隐藏校准案例。每张图都从已登记的证据图做无旋转、无缩放、无描字的矩形裁切，保留目标栏与必要相邻栏；统一的细红框只标出机器比较范围，不覆盖框内字形。案例顺序交错，审读包不含原书、版本、年代、页码、锚点编号、目标/校准角色或预期字串。

回答要求把字形判断与标点判断分开，记录图像是否足够、逐字置信度和所有不确定位置；不允许依上下文把疑难句改顺。协调时先看两个校准点，再按答案键中的门槛裁决目标点。两个审读者不一致、图像不足或校准失败时必须增加第三位审读者，不能用简单多数或“更通顺”替代字形证据。

运行方式：

```bash
npm run blind-review:adjudicate -- \
  --response private/blind-review/reviewer-a.json \
  --response private/blind-review/reviewer-b.json \
  --out private/blind-review/adjudication.json
```

第三份答卷使用第三个 `--response`。答卷和裁决结果应放在 gitignored `private/` 或仓库外；不提供 `--out` 时，结果只写到 stdout，经 `npm run` 管道读取纯 JSON 时使用 `npm run --silent blind-review:adjudicate -- ...`。输入不完整、独立声明不成立、使用 OCR/外部检索、规范化改变汉字、案例缺失/重复、审读者重复或输出文件已存在时，工具失败封闭。

## 输出合同

- 总状态为 `accepted`、`needs-third-reviewer` 或 `unresolved`。`accepted` 只表示三个目标点的汉字读法通过当前盲审门槛。
- 每位审读者先按两个校准点得到 `pass`、`conditional` 或 `fail`；`fail` 答卷不能单独支撑目标结果。
- 每个目标点分别输出汉字决定、标点决定、与答案键参考字样是否不同，以及每份答卷的可用性、置信度和校准状态。
- 两份可用答卷的汉字序列完全相同、至少一份校准为 `pass`，且不存在另一位校准通过者的高置信冲突时，汉字读法才可 `accepted`。
- 标点以保留位置的独立模式比较；低置信标点不参加标点共识，也不会阻止已经满足条件的汉字决定。
- `inputBindings` 保存答案键和每份原始答卷文件的 SHA-256。结果不包含外部专家身份认证，也不把局部文字决定升级为命理有效性或现实预测证据。

## 验收门槛

- 五张派生图的尺寸、字节数和 SHA-256 与答案键一致；答案键中的原始证据哈希能回接逐栏锚点。
- 任务单五个案例和回答模板五个案例一一对应，案例 ID 不重复，图像路径可读取，`focusColumnFromRight` 与答案键一致。
- 任务单、图片与答案键的红框坐标一致；回答模板同时收集整栏和红框字样，红框疑字必须显式标记。
- 审读目录中的文本不得出现见证 ID、源文件名、锚点 ID、页码、预期字样、目标/校准角色或答案键路径。
- 答案键实际为 3 个目标与 2 个校准；所有锚点存在于逐栏坐标 JSON，原始证据和派生图哈希均重算通过。
- 相关 JSON 可解析、本地 Markdown 链接存在，`npm run check` 通过。

## 验证结果

- `PASS`：任务单、回答模板和答案键的五个案例 ID、顺序、焦点栏与红框坐标完全一致；答案键实际为 3 个目标和 2 个隐藏校准点。
- `PASS`：五张带定位框审读图的尺寸、字节数和 SHA-256 均与答案键一致，并能按裁切与标框参数重建；五个原始证据哈希均回接有效逐栏锚点。
- `PASS`：审读目录文本未出现五个见证 ID、锚点 ID、PDF 页码、预期字串、源证据文件名、答案键文件名或任何案例到 `target/control` 的映射。
- `PASS`：裁决核心覆盖两位一致、两位高置信冲突、低置信标点、校准失败、第三位仍不能消解和污染/非法规范化六类行为；汉字与标点分别裁决，低置信标点不随汉字升级，第三位不能用简单多数压过通过校准的高置信冲突。
- `PASS`：使用真实答案键和两份临时合成答卷完成 CLI 端到端；结果为 3/3 目标汉字读法接受，答案键与两份答卷 SHA-256 均进入输出绑定；再次写同一路径以 `OUTPUT_EXISTS` 和退出码 2 拒绝覆盖。合成答卷只验证工具链，不是外部审读证据。
- `PASS`：3 个上游机器产物和 4 个实际取图扫描来源均反向登记盲审任务单；没有把未执行的外审写成已完成。
- `PASS`：非临时、非 `private`、非依赖与构建目录的 189 个 JSON 均可解析；本轮 6 个 Markdown 的 60 个本地链接存在。
- `PASS`：`npm run check`；TypeScript typecheck、191/191 tests 与 build 全部通过。

盲审只能提高局部字样判读的独立性。它不能证明古籍规则、命例归因或现实预测有效，也不能把一个版本的读法推广为唯一正文。
