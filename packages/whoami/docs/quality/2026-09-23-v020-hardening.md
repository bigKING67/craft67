## 已修复的确定性问题

| 问题 | 原风险 | 当前行为与回归 |
|---|---|---|
| 同一四柱候选只保存一个起运值 | 出生区间不跨时辰时，报告会把代表样本的起运日误写成唯一日期 | 每个候选汇总全部采样的 `cycles.uncertainty`，包含样本数、不同起运数、偏移与最早/最晚时刻；范围状态触发显式 warning。04:00±120 分钟样例复现并锁定 2003-06-25T15:00Z 至 2003-07-05T14:59Z |
| 输入事实可冒充候选分析覆盖 | 多候选紫微报告可只分析 C1，再给 C2 引用 `input.time` 通过 | 覆盖门禁按“候选 × 当前模式体系”统计非 input 事实；综合模式允许正文与 crossSystem 合并覆盖，但每个候选仍须同时有八字和紫微依据 |
| 春节前流年过滤使用公历出生年 | 2000-01-15 实属农历 1999，显式请求 1999 会被静默过滤 | 紫微保存 `birthLunarYear` 并以它过滤流年；1999、2000 两年均保留 |

## 来源与报告合同

输入增加可选 `provenance`，记录地点、经度、时区来源和核对时间；未知键、空对象和空值拒绝。它只是来源说明，不自动认证真实性。未提供时，context 生成 `input.provenance` 的 unverified 事实，Markdown 报告显示“未提供可核对来源”。

报告校验不允许 `input.*` 满足命盘分析覆盖；渲染和 Skill 同步要求 `cycles.uncertainty.status=range` 时写最早—最晚范围。八份主报告 JSON 以当前 chart/evidence 重新绑定，结构化 assertions 从新 context 取原值，并重渲染七份对应 Markdown；1996 compare、边界/财官 rule-review 与 cross-system 计算输出也已重算。旧质量记录和独立验收回执中的旧 ID 保留为历史证据，不改写成仿佛当时运行过 v0.2.0。

## 自然语言前向验收

新增 `acceptance-check` 和 `whoami.acceptance-run.v1`。清单绑定 Skill 快照、任务、rubric，以及每个 case 的输入、context、原始回答；所有文件验证 SHA-256、字节数、目录边界和符号链接实际目标。PASS 不能带非零问题计数。可选 `whoami.runtime-receipt.v1` 还必须逐项绑定模型/版本/推理强度/采样参数及 Skill、任务、输入、context、回答哈希；任一不一致即拒绝。文件级绑定不验证 provider 签名，缺可信回执时不得升级为 verified。

独立代理只读取固定 Skill 快照、任务与 context，未读取 rubric、源码、测试、其他示例或网络。合成输入为 2000-08-16 04:00±59 分钟、民用时、来源元数据缺失。回答正确保留候选 `C1-300a9bf9`、119 个不同起运结果、2003-06-26 01:01 至 2003-07-05 22:59 的民用时范围、代表值限制、2026 条件性解释和来源未核验；五项问题计数均为 0。当前运行无法提供可核对 provider/model/version 回执，manifest 如实使用 `UNVERIFIED` 和 null，最终状态为 PARTIAL。
