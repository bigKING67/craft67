# Fatetell 后续有界实验方案（尚未执行）

目的：识别服务端返回的信息、对输入变化的响应及报告一致性，建立可复现的行为证据。不是获取服务器私有代码或秘密提示词的承诺。

## 本轮离线复核

使用 reverse-craft R3 / web-api-identity，main_serial，无子代理、无新增浏览器会话或在线请求。复核原 case `20260923T024551Z-whoami-fatetell-mechanism-study-e78f`：1 evidence、1 finding，validate valid=true，无 errors/warnings。原 sealed case 保持不变。

原 E-0001 客户端片段显示：`created/running/done`、`result/is_unlocked/is_read` 及 `createReport/createFreePreview/markReportRead` 分支。可支持“有状态的报告创建与存取流程”；不支持“已找到后台排盘、旺衰、用神或模型算法”。记录的片段不足以复原完整请求与响应合同。

观察到后台输出稳定也可能源于缓存，不能直接归因于确定性规则；文案变化也可能来自采样、时间上下文或模板变化，不能直接归因于模型升级。

## 建议第一批：最多四份报告，先两份再决定是否继续

只使用合成档案，不借用当前真人档案；必须先确认允许创建合成档案及报告生成次数、额度上限。新增档案与生成报告均为外部写入。默认不删除已有档案，不购买，不自动重试；账户收费/权益不明确则停止生成。

建议输入：公历 2000-08-16、女性、东经 120 度、Asia/Shanghai。若站点地点只能选地名而无法指定经度，记录站点实际选择及返回坐标；无法确认则不能把太阳时差异单独归因于算法。

| 顺序 | 变化 | 待回答的问题 |
|---|---|---|
| A | 03:01，民用时；其余固定 | 返回哪些结构化命盘与报告字段？ |
| B | 同 A，仅打开真太阳时 | 校时是否改变时辰，盘面字段与文字是否一致变化？ |
| C | 同 A，仅改为 03:02 | 相同时辰内的微小变化影响哪些结论？ |
| D | 同 A，仅改为 02:59 | 跨时辰后，判断变化是否对应盘面变化？ |

先用 whoami 计算预期时间和候选作为比较材料，不把 whoami 输出当唯一正确答案。若无法锁定其他输入、生成选项或报告类型，单变量实验不成立，标记 INVALID SAMPLE。每次触发前检查已有/新建任务分支与可能的自动预览；自动预览也计入次数。超过预算停止，不以重进页面补救。

同任务重复读取只验证存取一致性，不算独立生成。重生成、额外追问均不包含在以上四次预算中，需要明确纳入操作范围后才执行。

## 取证与结论

每例记录脱敏输入、站点/客户端版本、操作时间、方法与路径、状态码、请求关联、任务状态、结构化字段与结果哈希。可核验输出需保存在 repo 外受控目录；不收集 Cookie、Token、邮箱、无关账户资料。四份中的成功/失败/缓存读取分别记账，不把 HTTP 200 视为成功报告。

优先区分：排盘差异、传统判断差异、表述差异、前提不明。只把可直接复现的输入输出记为 OBSERVED；对服务端内部实现的解释标为 INFERRED 或 UNVERIFIED。任何客户端生命周期副作用、权益变化或异步未知状态都先停止，保留现场，不自动重复或回滚外部数据。

后续有额度时可单独设计同输入独立生成与固定追问实验，比较核心判断一致性、引用与反证处理；不能从缓存命中率推断模型稳定性。
