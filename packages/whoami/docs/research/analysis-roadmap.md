## 验收分层

1. 计算事实：外部历法样例、输入边界与变形测试；不以竞品作为唯一真值。
2. 传统规则：每条候选规则记录可定位来源、流派、适用条件、反例和无法裁定的分支。先核对传统论证，不凭工程测试认定理论成立。
3. 报告质量：核对两体系的引用、支持与反证、用神口径冲突、紫微主题宫与限运作用链、追问是否凭新信息改写先前预测；独立于文风与篇幅评价。
4. 比较实验：固定模型、提示词版本、资料与时间口径；按命主拆分且答案隔离，记录拒答、错误事实与证据不足。Mingyu 与 MingLi 重合命例须去重，不把同源题库当交叉验证。
5. 自然语言前向验收：任务在回答生成前固定，产物用 acceptance manifest 绑定；评分记录事实错误、前提遗漏、候选混用、无依据时点和安全断言。semantic-forward-007 以冻结 v5 覆盖紫微五主题、结构化限运作用链与年度事件日程边界；008 以 v6 覆盖明年/后年解析、模糊大限改写与现实结果拒绝；009 覆盖 evidence 缺年时先停下、同 input 补算后更新 evidenceId；010 覆盖同一绝对时刻在不同 IANA 时区落入不同本地年份后再解析“明年”；011 覆盖混合公历、紫微农历年与八字立春年界时先停下，用户明确体系与年份后再生成报告；012 覆盖年度 evidence 被追问半年、季度、月、周、日时先停下，用户退回明确年度主题后再生成报告；013 覆盖“近期、不久、很快、过阵子、什么时候”等范围未定义的词先停下，用户明确选择年度后再生成报告；014 覆盖相对多年范围先改写为升序年度闭区间、缺年时停下补算、补齐后逐年绑定 timingChain；015 覆盖绝对月日星期与命名历法点分别停机，允许历史出生日期和裸年界说明，并在用户退回年度主题后继续保持未决；016 覆盖合法数字日期与日内时点用于事件判断时停机，同时保留出生时间、冻结日期和周期边界等非事件事实；017 先拒绝歧义或非法日期、钟点和非唯一时区，只有输入合法且唯一后才进入 evidence 粒度检查；018 对明确 IANA 时区的当地时刻继续分类 DST 缺失与重复小时，缺失时间不顺延，重复时间只按现实记录选择分支，分支确定后再进入 evidence 粒度检查；019 校验 ISO ZonedDateTime 的显式 offset 与 IANA 规则一致，允许回拨小时两个真实分支、拒绝错配 offset，并保持 DST 缺失时间优先失败；020 把合法的 IANA、offset 与 Z 表达统一归一化为绝对时刻，同一时刻只保留一个候选，不同绝对时刻则保留差异但仍受 evidence 粒度约束；021 以归一化端点组成明确时间区间，拒绝零长度、逆序和三端点串联，合并等价区间，要求先声明正时长重叠或拆成互斥窗口，并让合法区间继续受 evidence 粒度约束；022 拒绝用于事件选择的单边范围，要求声明时长唯一绑定区间并与 instant 差一致，跨 DST 时区分当地墙上时间与真实 elapsed time；023 要求重复日程先闭合绝对范围、补齐 IANA 地区时区并获得逐次 occurrence evidence；024 要求八字运年只使用结构化年度事实，拒绝升职年份强排，并把用户事后反馈保留为未独立核验的现实资料而非命中证明。没有实际运行回执时仍只可作维护者开发样例，不能升级为可复现模型结论。
