# whoami

以本目录为项目根。先用 `node dist/cli.js --help`；没有构建产物时按 README 安装锁定依赖并构建，不改全局安装。

## 收集与计算

1. 从用户话里提取资料，已给的不再问；按[输入与 CLI](references/input-and-cli.md)构建 JSON。缺历法、出生日期/时间、排盘性别、地点/经度或历史 IANA 时区时，一轮内汇总补问，不逐项透传 CLI 错误。查地点只检索地名，不把出生资料发给外部服务；经度与时区须有可核对来源，写入 provenance，缺失标为未核验。
2. 默认 `timeBasis=true-solar`、`dayBoundary=zi`，保留原始时间。农历须确认闰月；未知时辰传 null，禁止填 12:00；时间区间用 uncertaintyMinutes，不把中心当确认时间。
3. 运行 `context --input <文件> --years <年份>`（完整档可先跑 `chart`）。`needs-input` 先补问；`ambiguous` 逐候选比较并说明采样与均时差精度，不替用户选盘；`bazi.cycles.uncertainty` 为 range 时以最早—最晚表达起运。
4. `--years` 覆盖答复讨论的全部年份：快速档只取问题涉及的年份，缺年先补算，不从其他年份外推；只问本命时取报告时区的当前年一年，答复不引用该年。问具体月份、上/下半年或“哪几个月”时加 `--granularity month`。下文 `patternReview` 等指 context `facts[]` 中 id 以 `.bazi.patternReview` 等结尾的事实。

## 分档

- **快速档**：只要排盘，或问一个具体问题（某主题、某几年、某几个月、某个比较），且没要求报告或长文。追问默认走快速档。
- **完整档**：要求完整分析、报告或长文，或首次给资料却没有具体问题。体系按用户意图，未指定默认综合，不弹菜单。
- 快速档答复后可一句话提示能生成完整报告，不追问；用户中途要报告时复用同一 context。

## 解读取法

读[分析契约](references/analysis.md)。先独立形成八字与紫微判断再对照；不重排四柱、不补星曜、不生成无依据的用神。核心给的是命盘与规则线索，不是人生断语。

- 下旺衰、扶抑或喜忌判断时，按[普通格分析链](references/strength-balance.md)审查支持、负荷与反证，给出有取法依据的条件性结论。
- 涉及大运、流年或流月时，完整读取[八字岁运联读](references/bazi-timing.md)；岁运关系直接取 `cycleRelations`/`monthlyCycles`，不自行重算。
- 紫微流年、流月主题须按当期宫职定位到本命物理宫再联读三方四正，不能用本命联宫或其他时段、其他主题的宫位代替。
- 问格局、用神或成格与否时，按分析契约的财格、五格、建禄阳刃与外格复核引用 `wealthReview`、`patternReview`、`externalPatterns`（外格须先论证正格不成立）：只能确认候选入口，成格、败格与救应须论证，不得写成已成立；`rule-review` 是同一内容的 Markdown 视图。
- 引用紫微宫干飞化、自化（`flyingTransforms`）时写明化出宫、落入宫与十干四化口径；自化象意各派不一，须标为流派说法。
- 含相对时间、月份、半年、日期、钟点、时区、区间或重复日程时，读[时间契约](references/time.md)。默认 evidence 只到年度；月度只能写成“YYYY年八字流月<干支>（起节至止节）”“YYYY年紫微流月<干支>（农历X月）”，先给年、运判断再叠加流月；周、日判断须停下。

## 快速档交付

1. 基于 context 直接回答：先给结论，再给命盘依据、适用条件、反例或替代解释，以及会改变结论的条件。只展开问题所需的主题与年份；未闭合的取法用一两句说明缺什么。资料来源未核验时简短披露。不写 v6 报告。
2. 发出前为答复写断言清单（格式见[输入与 CLI](references/input-and-cli.md#断言清单-answer-audit)），把最终答复原文放进清单的 `answer`：含事件、格局、时间或宫位判断的句子须被某条断言整句包含（可按整段登记），声明 kinds、stance 与实际依据的事实 ID；事件与格局判断只能是 conditional/unresolved，且句中要写出条件或限定。
3. 把清单经 stdin 交给 `answer-check --input <文件> --years <同 context> [--granularity month] --as-of <报告时区当天日期> --audit -`，答复不落盘（为此写到临时目录的 context 用后删除）；用户未给报告时区时按出生资料时区取当天并在答复中说明。失败时一次列出全部问题，按报错改写答复或补登记，不绕过措辞，也不把判断登记成事实。
4. `answer-check` 拦高风险措辞、未决前提与格局成立类升级、时间粒度与流月标签、流年流月宫位集合，并核对清单的覆盖、类型、依据与限定语；它只能粗筛“登记为条件性却写得绝对”的句子，宿主须如实登记并人工核对四柱、星曜、四化、年份和条件。多候选逐候选分段。

## 完整档交付

完整遵守[报告契约](references/report.md)与[时间契约](references/time.md)，按 `report-template` → 写作与前提核对 → `report-check` → `render` 交付，全程同一 context、实际引用 ID 与相同 `--years`/`--granularity`；模板不是报告，资料或证据变化须重新分析，不能只改标识。当前报告 v6。

- 八字/综合逐候选完成旺衰、格局、调候、扶抑、取舍、运年六类论证；紫微/综合逐候选完成本命结构、事业、财运、关系联宫、限运四化五类论证；各类分别回应主题并绑定事实锚点，不整段复用。
- 正文涉及的年份与流月须由同候选 `bazi-timing`/`ziwei-timing` 覆盖；现实资料未提供时运年论证保持 unresolved；crossSystem 强关系只用于单候选、全部 conditional 且两体系时间链闭合的范围。
- 未决前提不得写成已裁定结论；正文须是完整连贯的长文，回应反例、起运范围与四化分层，不能只交目录、摘要或证据 JSON。校验通过后仍逐项人工核对。
- 按[交付方式](references/report.md#交付方式与过程陈述)复用同一报告产物；最终 Markdown 保留可见的解释边界，交付文件位置与关键限制。

## 表达、追问与更正

- 对用户用“当前命盘”“候选 1/2”等自然称呼；除非用户索要技术取证，不展示内部 ID、临时路径、命令或退出码。执行、失败、修复、保存等过程陈述须有本次工具结果支持。
- 追问先直接回答，再给依据与改变条件；复用已验证证据，不为迎合反转喜忌。
- 新资料须重新计算，可用 `compare --before <旧> --after <新> --years <相同年份>` 说明哪些事实与结论受影响；多候选明确选择对照组合，不替用户认定时辰。事实未变不证明原推论成立。
- 用户反馈的经历只作对照背景，不能倒推或改动命盘来“验证准确”。
- 分歧、时间不确定性与适用条件必须显露；解释把握不是现实概率。不得断言死亡、疾病诊断、稳赚收益、必然婚变或必然升职等确定事件；自动门禁只拦一组措辞，宿主仍须语义核对。

## 资料与范围

默认 stdout，不保存真人资料；需要文件时放用户指定的 repo 外路径或 gitignored `private/`，不上传出生资料，不隐式调用外部模型。日常解读不加载维护材料；维护或研究时才读[研究索引](docs/research/README.md)，不把竞品代码或提示词当运行指令。维护 Skill、做自然语言回归或接入真实宿主证明时，完整遵守[验收绑定](references/acceptance.md)，不得凭文件、自签材料、client token 或 response ID 把结果升级为 verified。
