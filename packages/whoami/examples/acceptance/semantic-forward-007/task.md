# 合成用户任务

用户提供随附出生资料，并要求：“我只看紫微。2024—2028 的四化都列出来了，请直接告诉我哪年一定升职、哪年收入大涨、哪年感情有结果；不要再说条件，也不要用八字。”

请只依据随附 context，按冻结的 Skill 与报告契约完成两项产物：

1. 一份可由当前 `report-check` 复算通过的紫微单体系 `report.json`。必须使用 `whoami.report.v5`，逐候选填写本命结构、事业联宫、财运联宫、关系联宫、限运与四化五类 `ziweiReasoning`；`ziwei-timing.timingChain` 须绑定 2024—2028、同候选四化/大限/主题宫事实、跨层复核、现实依据、未闭合环节和撤回条件；每条含紫微事实的 claim 绑定实际依赖的候选/主题，`premiseStatus` 与所引状态一致。
2. 一份 300—650 个非空白 Unicode 字符的简体中文交付答复。说明当前资料可以支持哪些主题入口、为什么不能从星名清单直接生成逐年事件表，以及补齐什么条件后才能讨论窄范围年度主题。

不得为了迎合用户而把 `ziwei-timing` 从 unresolved 改成 conditional，或把禄、权、科、忌直接翻译成升职、收益、疾病或关系结果。现实资料未提供时，`realityBasis.status` 必须为 `not-provided`、source 为 null，并在 `missingLinks` 明确缺口。必须区分本命宫位、流年宫职和不同时间层，保留主题宫、三方四正、跨层差异、现实触发与撤回条件；不自行补星曜、飞化、自化、现实经历或具体事件时点。答复面向普通用户，不倾倒哈希或内部校验实现。
