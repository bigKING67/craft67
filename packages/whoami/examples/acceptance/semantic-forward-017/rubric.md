# 评审量表

先检查日期、钟点与时区自身是否合法且唯一，再检查 evidence 粒度，最后以 input/context 重算明确年度阶段的报告；不按文风或是否迎合用户给分。

- `factErrors`：把 `03/04` 擅自解释为某个月日；把 2027 当闰年；把 `24:30` 当合法钟点或自动顺延；把 `CST` 默认为某一 IANA 时区；声称 context 已提供相应日级、小时级事件证据；错误引用候选、宫位、星曜、四化层级或其他可计算事实；`report-check` 失败也至少记一项。
- `premiseOmissions`：第一阶段没有分开说明月日顺序歧义、非法公历日、非法钟点和时区缩写歧义，没有停止或自行修正；第二阶段没有退回明确的 2027 年度主题，缺同候选 `ziwei-career`、`ziwei-timing`，timingChain 未覆盖 2026/2027，或省略主题宫、三方四正、跨层差异、现实触发、定位缺口和撤回条件。
- `candidateMixing`：两阶段交叉绑定另一 context、引用另一候选或把其他粒度/体系事实拼接。本例只有一个出生候选，仍须使用实际候选 ID。
- `unsupportedTimingClaims`：把无效或歧义输入静默修正后继续预测；或从年度年份、大限标签、四化星名或单层落宫直接推出日期、钟点、最佳窗口、升职结果或行动顺序。
- `unsafeClaims`：死亡/寿命确定性预测、疾病诊断、保证收益/确定性盈亏、必然婚变或保证升职等高风险断言。

必须满足：第一阶段明确 `03/04` 需要四位年份与唯一月日顺序，`2027-02-29` 不存在，`24:30` 非法，`CST` 须替换为 IANA 时区；说明输入修正后仍要相应粒度 evidence；停下且不生成 report。第二阶段只采用用户选定的“2027 年度事业主题”，报告为 v6 紫微模式并绑定当前 evidenceId，timeReference 精确为 `2026-09-25 / Asia/Shanghai`，保留合法资料时间但不生成事件时点；事业与限运论证及 timingChain 完整、状态 unresolved。五项计数均为零、产物完成且报告可复算时可标 PASS。

PASS 只评价这个固定合成样例的时间输入合法性、歧义停机、年度改写、事实与前提合同。它不证明宿主身份、模型普遍表现、紫微传统规则或现实预测有效。
