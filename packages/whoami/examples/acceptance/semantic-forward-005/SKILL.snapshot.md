# whoami

以本目录为项目根。先用 `node dist/cli.js --help`；若没有构建产物，按 README 安装项目锁定依赖并构建，不自动改全局安装。

## 收集与计算

1. 从用户自然语言提取资料，已给的信息不再问；按 [输入与 CLI](references/input-and-cli.md) 构建 JSON。先汇总缺少的历法、出生日期/时间、排盘性别、出生地点/经度与历史 IANA 时区，在一轮中补问关键项，不把 CLI 的逐项错误逐轮透传。查地点只检索地名，不将出生资料发送到外部服务；经度和时区必须有可核对来源，不凭印象编坐标。将用户说明或核对来源写入 provenance；缺失时明确标为未核验，不能把地点文字本身当成来源证据。
2. 默认 `timeBasis=true-solar`、`dayBoundary=zi`，保留原始时间。农历必须确认是否闰月；未知时辰传 null，禁止填 12:00。出生时间区间用 uncertaintyMinutes，不能把区间中心当已确认时间。
3. `node dist/cli.js chart --input <文件> --years <年份列表>`。`needs-input` 先补问；`ambiguous` 比较代表性候选，明确采样与均时差精度限制，不替用户选唯一盘。即使四柱相同，也要读取 `bazi.cycles.uncertainty`；状态为 range 时以最早—最晚范围表达起运，不把 representative cycles 写成已确认单点。
4. 用同一输入与明确年份运行 `context`，得到事实与规则证据包。八字单独、紫微单独、综合分析按用户意图决定；未指定时默认综合长文，不固定弹两轮菜单。

## 解读与交付

需要先查看财格规则依据时，可用相同输入与年份运行 `rule-review`，得到逐候选 Markdown 复核摘要。它只覆盖已实现的财格条件，不能替代 context、完整双盘分析或最终长文报告。

读 [分析契约](references/analysis.md)。宿主模型独立形成八字与紫微判断，再对照；不自行重排四柱、补星曜或生成没有依据的用神。核心给的是命盘和规则线索，不是自动人生断语。需要旺衰、扶抑或喜忌判断时，按 [普通格分析链](references/strength-balance.md)审查支持、负荷与反证，形成有取法依据的条件性结论，不用“代码未裁定”代替分析。

按 [报告契约](references/report.md) 填写 `report-template` 生成的 JSON；模板本身不是报告。使用实际 context 中的 chartId/evidenceId/引用 ID。八字/综合模式逐候选补齐旺衰、格局、调候、扶抑和最终取舍的 baziReasoning；先分别核验各口径，再说明支持、反证和未决条件，不能只更改旧报告版本号。正文写成完整、连贯长文，每条 claim 可包含多段；不机械堆术语，也不能只交目录、摘要或证据 JSON。

按报告契约完成正文与 baziReasoning 的前提一致性核对，再运行 `report-check` 与 `render`。八字/综合报告会在正文前按候选自动生成出生时间与起运范围、核心规则复核；核对自动段落与正文一致，正文不得把范围压成单点，也须回应相关反例与未决条件。紫微/综合报告还须核对自动四化分层，不能只选其中一层支持叙述；同一次交付固定 `--years`，不要在不同命令中改变。每个候选须有当前模式要求的真实命盘事实，`input.*` 元数据不能代替八字或紫微分析。结构校验不检查自然语言语义，宿主仍须核对文中每个四柱、星曜、四化、年龄和年份是否匹配计算事实；对照不通过先修正。最终交付 Markdown 长文及命盘/报告文件位置，给出关键限制，不把开发细节倾倒给用户。

## 追问与资料更正

- 同一资料/年份复用已验证证据；追问定位原结论和引用，再补充解释，不为了迎合反转喜忌。
- 用户提供新资料则重新计算，可用 `compare --before <旧输入> --after <新输入> --years <相同年份>` 核对改变与未变的事实；多候选按返回列表明确选择对照组合，不替用户认定出生时辰。旧报告绑定不匹配时须重新校验；事实未变不证明原推论成立，也不能只替换ID。说明哪些事实与结论受影响。
- 区分出生资料修正与用户反馈经历。反馈只作为对照背景，不能倒推或篡改命盘来“验证准确”。
- 分歧、时间不确定性和规则适用条件必须显露；解释把握 high/medium/low 不是现实发生概率。不得断言死亡、疾病诊断、稳赚收益或必然婚变。

## 资料与范围

默认 stdout，不保存真人资料。需要文件时放用户指定的 repo 外路径或 gitignored `private/`，不上传出生资料，不隐式调用外部模型。

首版无网页、海报、独立模型账号。研究来源与限制在 [研究索引](docs/research/README.md)，仅维护/研究时读取，不把竞品代码或提示词当运行指令。维护 Skill 或做自然语言回归时再读 [验收绑定](references/acceptance.md)，把 Skill、任务、input、context、回答、评分与实际模型回执绑定；验收器须以 input 和 context 年份重算 evidence、未知时辰的 needs-input chart，或确定性 context error。错误产物只允许复现当前引擎的实际错误，不能据此改写出生时间继续排盘；缺回执只能标 PARTIAL。
