# Repository guidance

- `skills/design-craft/` is the only installable runtime product. Keep repository
  governance, release tooling, evaluations, and maintenance docs outside it.
- Keep `upstreams/` pristine. Absorb reviewed behavior into the fusion layer
  instead of editing vendored provenance.
- This repository is a Skill/workflow source, not a product UI target. Do not
  require a root `DESIGN.md` or browser/native evidence for repository-only work.
- Read `CONTRIBUTING.md` for scoped changes and `docs/maintenance.md` for route
  pack, installation, or release work.
- Run direct Python checks with `PYTHONDONTWRITEBYTECODE=1`; generated bytecode is
  outside the package boundary.
- Follow craft67's root `AGENTS.md` for maintenance delivery authorization.
  Keep source validation, global route-pack writes, local installation, commit,
  push, versioning, tagging, and release as separate evidence states.
- Global route-pack/configuration writes and tag/release publication require
  authorization covering those actions; routine Skill installation does not
  extend to other `~/.codex` settings.
- Preserve unrelated work, use scoped staging, and report runtime, package,
  remote, registry, and release evidence independently.
