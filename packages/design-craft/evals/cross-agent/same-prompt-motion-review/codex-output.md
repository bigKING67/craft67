**Verdict: block implementation approval on the static interaction contract.** Motion has a valid purpose here, but the supplied implementation does not establish reliable pointer ownership, continuous interruption, or Reduced Motion behavior. This is a design and source review—not an observed finding that the sheet feels slow or jumps.

**Evidence level: L0 static, with supplied product context.** Only the prompt and code were assessed. Reading this as a repeatedly used web operations sheet, with calm utility styling, optimized for changing workspace height while preserving task context.

Motion should exist for direct pointer tracking and a restrained release-to-snap transition. Pointer tracking must not have an independent easing or duration. Remove whole-sheet press scaling, blanket property transitions, decorative bounce, and any animation-dependent input lock. Content, focus, and task availability should not wait for settling to finish.

The following five findings block approval; priorities reflect source-level contract defects, not measured runtime severity. Repairs and acceptance checks refer to the numbered moves and validation plan below.

Eight concrete design moves:

1. **M1 — Immediate, local pointer-down feedback.** Change the drag handle’s color or surface treatment immediately on eligible down; clear it on release/cancel. Remove `scale(0.96)` from the sheet. A large working surface should retain stable content geometry while acknowledging the grab.

2. **M2 — Give the gesture one owner.** Use explicit idle, pressed, dragging, and settling states with one active `pointerId`. Start from a dedicated handle, capture the pointer, ignore additional pointers, and handle `pointercancel` and lost capture. Use a provisional 8–12 CSS-pixel intent threshold, tuned to the handle and touch testing; ordinary taps must not trigger a settle. Scope touch handling to preserve scrolling inside sheet content.

3. **M3 — Track 1:1 in one coordinate space.** Record the current presentation position `y₀` and pointer position `p₀`; inside valid bounds, use `y = y₀ + (p − p₀)`. Preserve that origin through the intent threshold. Drive translation through one transform owner, with no positional CSS transition during drag. Cache geometry outside the move loop and coalesce rendering to animation frames. Replacing `top` reduces a layout-animation risk; it does not prove smoothness.

4. **M4 — Interrupt from the visible position.** Retain a motion controller that exposes current position and velocity. On re-grab, sample that presentation state, transfer position ownership, cancel the old settle, and establish the new grab offset without reverting to its start or target. Pointer motion then owns position; animation-to-animation retargeting inherits current velocity. Commit the final base position and logical snap state, clear the old effect, and guard cleanup against stale completions.

5. **M5 — Hand release velocity into settling.** Estimate velocity from a short recent history of position and monotonic time samples, in **CSS px/s**; discard stale samples after a pause. Feed bounded velocity and current presentation position into a critically damped settle, converting units to the API’s requirements. A roughly 0.25–0.30-second response scale is a tuning hypothesis, not a fixed duration or validated setting. Avoid deliberate bounce and keep input available.

6. **M6 — Separate endpoint projection from target selection.** Preserve nearest-current-position targeting unless momentum targeting is explicitly adopted. For an auditable experiment, compute `vBound = clamp(v, −vMax, vMax)` and `yProjected = clamp(y + vBound × 0.15s, yFull, yCollapsed)`, using downward-positive CSS coordinates. Choose and document `vMax` during tuning. Only the momentum variant selects the nearest snap to `yProjected`; the existing variant selects nearest to `y`. Both can inherit velocity through M5.

7. **M7 — Add restrained soft boundaries.** Keep 1:1 tracking between full and collapsed; apply progressive resistance only beyond those outer bounds. For signed overshoot `d`, a candidate is `displayedOvershoot = L × d / (L + |d|)`, where `L` is a small, tested maximum excursion in CSS pixels. Half is a snap point, not a rubber-band boundary. Recover without decorative oscillation; remove elasticity under Reduced Motion.

8. **M8 — Make Reduced Motion an explicit path.** Honor the preference in both JS settling and CSS feedback, including changes during an active animation. Preserve user-controlled tracking, but remove autonomous large travel, momentum continuation, elasticity, and scale. On release, commit the selected state immediately with persistent handle/state feedback; a brief local color or opacity cue may remain. Provide labeled keyboard-operable state controls so changing height never requires a drag.
