# Web concept-image direction

Use only when the requested deliverable includes website design images or
section comps. Keep generation optional: visual importance, a new page, or a
supplied reference does not itself require an image call.

## Shape the requested output

Resolve audience, primary job, required content, selected style, image count,
aspect ratio, and usable resolution from the brief. A hero request stays a hero;
a specified set must be complete. Do not turn an unspecified page into six or
eight generations, require a horizontal frame per section, or add sections to
fill a funnel template. A full-page comp is valid when its details are readable.

Keep project DESIGN authority, supplied assets, and approved factual copy above
generic aesthetic options. Use `visual-judgment.md` for direction choices and
`surface-playbooks.md` when the page's job needs more specific guidance.

## Compose a useful generation brief

Describe the intended artifact and viewport, content hierarchy, dominant
text/media relationship, layout proportions, type roles, palette roles, CTA
family, imagery/crop, and the elements that must remain unchanged. Separate
exact required copy from concept copy. Use real facts for proof, logos, metrics,
and testimonials; do not ask the generator to invent credibility.

Choose composition from content: centered statements, editorial splits,
image-led asymmetry, galleries, and type-only openings are options. Change
density, scale, media/text ratio, or whitespace where the narrative needs it,
not to meet a novelty quota. Make required text and controls readable.

Across multiple frames, preserve palette, display/body scale, spacing, CTA
geometry, icon/illustration language, photographic treatment, and copy voice.
Carry approved visual anchors into the next prompt instead of redescribing a
different design system. Hover, pinned stories, or stacking cards depicted in
a comp need a separate interaction specification during implementation.

## Execute within the real tool contract

Use the host's available image-generation/editing capability and required tool
or Skill instructions. Do not assume a provider or model exists, simulate a
tool call, or treat a written prompt as a generated image. Tool availability
does not authorize additional paid calls or uploading sensitive assets.

Reuse existing authorization for the agreed set; do not introduce per-section
approval checkpoints. Identify a concrete defect before another pass, retain
the best candidate, and stay within the agreed scope and budget. Stop when the
requested output is adequate, improvement stalls, or a material cost/authority
boundary requires a decision. If generation is unavailable, provide a brief
only as an explicitly labeled fallback, not as a completed image deliverable.

Inspect actual images for composition, text, missing sections, asset fidelity,
and cross-frame consistency. Return the requested images with concise labels
and honest failed/missing outputs. A comp proves neither implemented behavior
nor responsive quality, accessibility, or browser performance.

For authorized implementation, use `image-reference-implementation.md` with
the selected image. Do not regenerate it merely to inspect a crop or begin a
new approval ceremony when the direction and implementation are already agreed.
