# 财务数据与证据

## 来源优先级

1. 目标法域的监管机构、交易所、发行人/基金管理人正式披露和法定报告。
2. 发行人 IR、基金文件、指数方法、债券发行文件及与法定披露一致的正式材料。
3. 适用市场的结构化数据 Provider；Fuyao 覆盖 A 股，可选 yfinance 覆盖港美股二级数据，用于检索、时间序列和交叉核对。二者都不替代正式披露。
4. FRED/ALFRED、统计机构、央行、财政部门、行业组织和其他可追溯公开来源，用于宏观序列、历史 vintage、补充或独立交叉验证。FRED 聚合的第三方 series 仍需保留原来源和权利说明。

财务报表与公司行动以正式披露为最终口径。行情和估值快照保留 Provider、request ID、抓取时间和数据时间，不把它们伪装成财报事实。

宏观 capture 还必须保存 series id、标题、原来源、单位、频率、季调、观测区间、变换代码、抓取时间和 real-time/as-known-on 日期。观测日期不等于发布日期；`.` 是缺失值而不是零。历史研究和回测默认使用 ALFRED vintage，只有讨论“今天最新修订后的历史”时才使用未指定 as-known-on 的 FRED mode。

## Provider 运行与凭据边界

配置、持久运行数据和缓存默认分别位于 `~/.config/money-craft`、`~/.local/share/money-craft`、`~/.cache/money-craft`。`MONEY_CRAFT_CONFIG_HOME`、`MONEY_CRAFT_DATA_HOME`、`MONEY_CRAFT_CACHE_HOME` 或对应 XDG 变量可覆盖各自路径，且覆盖值必须是绝对路径。源码开发只能用 `MONEY_CRAFT_ENV_FILE` 显式选择由当前用户拥有且权限受限的 dotenv 文件；运行时不搜索 cwd 或父目录。 显式 env 文件拒绝末级符号链接，读取时校验文件身份/权限并限制字节数；先验证全部内容再更新环境，解析失败不留下已加载变量。已有进程变量即使为空也优先；不执行或展开 shell 表达式。父目录可信性、同一文件 inode 的外部并发写入及 Windows/NFS 行为不由此检查保证。各 Provider 的 key 位置、解释器和依赖要求仍以对应 Provider reference 为准。

可选数据依赖安装在专用数据运行时 `~/.local/share/money-craft/venvs/data`（随 `MONEY_CRAFT_DATA_HOME`/`XDG_DATA_HOME` 移动）。系统 `python3` 启动 `money_craft.py` 时，只要该环境存在，入口会透明切换到它；在报告 venv 或其他显式 venv 中运行时不抢占解释器。`MONEY_CRAFT_DATA_PYTHON` 可直接指定受控解释器；旧 `~/.config/money-craft/data-venv` 仅在新环境不存在且路径未显式覆盖时作为迁移兼容回退。不要恢复 cwd 搜索或全局安装。

不得将 key 放进命令行、完整请求 URL、capture、错误文本、报告或 Git。Provider 缺失、依赖缺失、限流或目标不受支持时形成可见 `PROVIDER_GAP`；没有适用于结论的当前正式或可追溯来源时，停止事实型判断，不能用缓存或模型记忆补齐。

## 口径与差异

比较前必须统一 `security_id`/share class、财政报告期、真实期末日、会计准则、合并范围、币种、单位和累计/单季口径，以及指标定义（例如净利润与归母净利润）。未确认可比时先标记 `UNVERIFIED_BASIS`，阻断依赖可比性的估值与结论；不能套用下列百分比阈值判定一致或冲突。可以展示两个原始数值的表面差异，但须注明它不是同口径误差。完成口径对齐后才计算用于分级的差异率：

```text
abs(source_a - source_b) / max(abs(source_a), epsilon)
```

- `<= 1%`：仅可描述为跨来源数值接近，仍记录两个来源；不能仅凭幅度认定差异来自舍入。
- `> 1%` 且 `<= 5%`：显式展示差异和可能原因，正式披露优先。
- `> 5%`：阻断依赖该数字的估值和结论，回到原始报告核实。

常见原因包括单位、累计与单季、合并范围、披露更新时间、复权、股本变化和非 GAAP 口径。`null` 表示未披露，不得补零。

### 分项与披露合计的核对

上述跨来源百分比阈值不适用于同一披露内的恒等关系或分项加权核对。引用分项推导总收入、成本、利润率或其他关键合计时，分别保留披露值和复算值，用同口径分子/分母或权重重建，再计算残差；不简单平均产品利润率。先核对原表、单位、权重、产品组合、期间及模型版本，不能因为来源正式就假定内部一致。

“舍入可解释”须有显示精度与舍入方式的依据，并以可重算的误差上界或区间覆盖残差；精度或规则未知时保留未核对一致，不能拿1%阈值代替舍入分析。残差非零且原因未明时，展示两值、定位和待解释差异，阻断依赖该值的确定性估值；允许明确标注采用哪组输入、保留冲突的条件敏感性演示。不得静默选值、擅自归因，或为通过审计而放宽 `tolerance`。

复用现有 `financial_rigor.calculate/audit_text`，不要另写审计脚本或读取源码找入口。多个计算在一次 Python 调用里批量生成回执，不要逐条调用 `financial_rigor.py calculate` 命令行：

```bash
python3 - <<'PY'
import json, os, sys
sys.path.insert(0, os.path.join(os.environ["MONEY_CRAFT_SKILL_DIR"], "scripts"))
from financial_rigor import calculate
for cid, op, inputs in [("C01", "subtract", ["90", "100"]), ("C02", "divide", ["15", "20"])]:
    print("<!-- money-craft-calc: " + json.dumps({"id": cid, "operation": op, "inputs": inputs,
          "expected": str(calculate(op, inputs)), "tolerance": "0.000001"}) + " -->")
PY
```

把输出的回执写入交付 Markdown，最后只审计一次：`python3 "$MONEY_CRAFT_SKILL_DIR/scripts/money_craft.py" audit financial <answer.md> --json`（`audit report`、`audit reconciliation` 同形），`valid: true` 即回执全部复算通过。正常计算回执验证复算值及残差；需要检验“精确相等”主张时，另用 `subtract`、`expected: "0"`、`tolerance: "0"` 的诊断回执。保留不相等的失败诊断，正文用真实残差回执交付并明确未决状态，不把诊断改成通过。计算审计通过只证明输入下的算术；它不自动提取披露表格、不证明舍入原因，也不检查是否遗漏了应做的合计核对。

跨币种研究保留原始报告币种与换算值，记录汇率类型、来源、时间戳和方向。资产负债表、利润表、现金流、股价和企业价值若使用不同日期汇率，必须解释；无法获得可比汇率时不做伪精确横向排名。

涉及净现金、企业价值或资产折价时，再统一现金定义、受限/质押状态、债务科目、租赁口径、少数股东权益和估值日股本。数据接口未返回某个负债或受限资金科目，不等于该科目为零；先回正式报告附注，仍无法确认时阻断依赖该输入的精确结论。

局部问题只要要求解释现金可用性、母公司分配能力、融资负债纳入/重分类、受限资金扣减或产品到期/解押，也须读取并应用 [research-semantic-review.md](research-semantic-review.md) 的“现金、债务与法人边界”；quick/chat 或只算一个科目不豁免。纯转录给定数值、单位换算而不作上述经济解释时，不因出现现金或债务字样额外加载。

发生追溯重述或会计差错更正时，每个期间必须显式标注 `reported`、`restated` 或 `comparable-estimate`。优先使用同一份正式报告内的重述后比较列；只有原始输入、公式、单位、来源和可重算的 `calculation` 都完整时才允许可比估算。现金流未受重述影响也要由正式原文确认，不能凭报表外观推断。

## 业务进展到财务结果的证据边界

涉及客户导入、商业化或订单兑现时，按原文条款判断支持范围，不把以下类别当作必经的线性流程或自动升级关系：

| 材料或事实 | 可以支持什么 | 继续推导前要核验什么 |
|---|---|---|
| 合作意向、框架协议 | 合作范围和方向；若含具体采购义务，另按条款评价 | 有无约束数量、价格、期限、退出条件；不得仅凭标题计入订单 |
| 验证通过、供应商定点 | 指定产品或项目的导入进展 | 最终采购义务、份额、单车用量、量产及交付条件；生命周期需求预测不是年度保证采购 |
| 采购订单或合同 | 条款范围内的订单规模和履约安排 | 是否生效、取消/调整条款、最低采购义务、币种税额、执行期间与截止日未履约余额；不能因存在条件就把真实订单一概归为意向 |
| 出货、交付或客户验收 | 对应批次履约进度 | 控制权转移、验收及发行人收入确认政策；交付金额、订单金额和收入不能重复相加 |
| 已确认收入 | 对应期间与合并范围的会计结果 | 成本、费用、税项及权益归属，区分毛利、项目利润、集团归母利润；不套用成熟产品毛利率推算新产品利润 |
| 预收、开票或回款 | 各自的结算与现金进度 | 是否含税、是否对应已确认收入、应收/合同负债及退款条件；现金收取不自动证明收入或利润已实现 |

每个影响判断的项目保留来源、披露/观察时点、客户及产品范围、数量单位、金额期间、约束与条件，以及仍缺失的下一环证据。台车、零件套数和项目生命周期不能未经转换混算；同一合同在订单、交付、收入中的不同状态不重复计数。比较订单覆盖率或从订单推盈利前，先统一分子分母的产品、期间和确认口径。

在手订单应按截止日未履约范围理解，并核对发行人的具体定义；缺取消、履约或余额资料时不自称已经独立验证全部存量。发行人转述客户需求不等于客户侧独立确认，未提供最新订单也不等于没有订单。最终结论同时保留已获支持的进展和不能跨越的推导，不为凑齐模型编造成交价、交付时点或利润率。这些是来源语义检查，计算回执不会自动验证合同效力或会计确认。

## 时间与复权

- 研究记录 `as_of`、报告期、披露日、行情数据时间和抓取时间。
- 当前快照使用实际成交价；历史价格走势比较默认使用前复权并注明复权基准日。历史时点的市值、PE/PB、企业价值及安全边际使用当日实际报价，不能直接拿含后续分红调整的价格乘当时股数或除当时 EPS；拆股须同步对齐价格、股数及每股指标。总回报研究必须明确分红和复权口径。
- 同一张表或公式不得混用复权与不复权序列。

## 证据捕获

Provider 命令使用 `--capture-dir` 和 `--source-id S01` 保存脱敏请求、原始响应和 SHA-256 manifest。公开仓库中的 capture 目录必须位于已忽略的 `local/evidence/<case-id>/`；正式公告或网页证据也保存在该私有目录，并记录 URL、抓取时间、本地相对路径和内容哈希。

关键来源文件的哈希检查使用独立工具调用，保留成功退出码和实际摘要输出，再与指定摘要比对；不要与 PDF 提取等命令串联。工具记录未返回实测摘要时，不能用输入提供的哈希或最终回答自报代替已核验，应独立补验或明确核验未完成。

正文用 `[S01]` 引用。公开报告的来源索引必须能解析到正式 URL 或公开 `evidence-manifest.json` 条目；manifest 只发布来源元数据和 SHA-256，不发布 Provider payload、下载的公告或网页快照。关键计算使用 Decimal，并在最终回答中嵌入下列回执；这同样适用于 quick/chat 筛选，不以“已用 Decimal 复算”或自然语言公式代替回执，也不因此扩展为完整报告或归档：

```html
<!-- money-craft-calc: {"id":"C01","operation":"multiply","inputs":["10.5","20"],"expected":"210","tolerance":"0.000001"} -->
```

回执 `id` 使用 `C01`、`C02` 等编号（大写 C 后接两至七位数字），不得使用 `CALC_REV_DIFF` 等描述性名称；每条编号唯一。支持 `add`、`subtract`、`multiply`、`divide`、`cagr` 和 `weighted_average`。审计失败时先修事实或公式，不删除回归门禁。

回执中的 `inputs` 与 `expected` 使用程序生成的 Decimal 数值字符串，保留计算精度；只在正文展示时取整，不把展示后的数值抄回回执。`tolerance` 是相对误差上限，不是允许的小数位数；接近零的百分点差尤其不能靠固定保留六位来保证通过，也不应为迁就取整而放宽容差。交付前对最终包含回执的回答文本实际运行 `financial_rigor.audit_text`（纯聊天可在内存中执行，无需创建正式档案），或对已保存文本运行 `financial_rigor.py audit --report <path> --json`；仅计算中间值不算完成最终回执审计。若失败，修正回执生成并重新检查，保留原失败记录。

回执须覆盖正文用于判断的最终推算值，而不只是中间比率：例如比较两期利润率时，两期比率及其百分点差都要可重算。比例与百分数的单位需明确，避免将比例差直接标作百分点。交付前逐项对照正文的关键变化值与回执；已有回执全部通过，不代表关键计算已覆盖完整。

### 计算审计的解析边界

`money-craft-calc` 支持多行 JSON；每个标记都必须形成完整对象。损坏、未闭合或嵌套的标记会导致审计失败，不能因存在其他正常收据而忽略。报表勾稽 JSON 的小数按 Decimal 读取，避免先转二进制浮点抹掉差异；超出解析或运算范围时返回审计错误。

勾稽项的期间必须属于 `period_basis`，累计转单季项还必须对应 current 期间。所有操作数须由研究者事先统一单位和口径；`unit` 标签不是自动单位换算或来源语义核验。结构和计算通过不代表正式报告摘录已核实。

报告引用审计只排除“来源索引”章节本身；索引后的附录和其他正文仍需解析引用。来源定义必须在同一行提供目标，空目标不能借用下一行文字。报告 `as_of` 使用规范 `YYYY-MM-DD` 自然日，不接受紧凑日期或 ISO 周日期。上述语法核验不能替代链接目标、原文真实性及论点支持的核验。
