## 判定方法

分别判定：

1. 宿主是否实际成功读取 `SKILL.md` 和相关引用；文件存在或模型自报不足以证明加载。
2. 回答是否满足案例标准，推断、时间和数据口径是否正确，由主代理逐条人工复核。
3. 关键计算是否有机器可重算回执，并通过财务审计。`valid=true` 且零项检查不是计算合同通过；无需计算的回答可明确记为 `NOT_APPLICABLE`。

`host.json` 中宿主进程退出 0 只表示模型运行完成。当前 Runner 在写入宿主证据后自动生成 `machine-audit.json`：自身退出 0 表示机器检查通过，退出 4 表示机器门禁未通过；历史运行保留原退出语义，不回写。Runner 永远输出 `REQUIRES_MANUAL_REVIEW`，不会自动给语义 PASS。失败保留原回答与审计；仅根据已观察到的问题修正 Skill，再以原问题、新目录重跑，不修改旧产物或降低标准。

### 机器门禁

可对已有运行离线复核，不重跑模型、不修改旧证据：

```sh
python3 scripts/audit_skill_task.py --run-dir local/skill-evals/<run>/<case>
```

本轮在 `cases.json` 增加显式 `machine_contract`：五个投资案例要求宿主路由，上游维护不要求；跨市场身份不明允许 `AMBIGUOUS_SECURITY` 阻断回执；财报、复盘和筛选要求计算回执。其余案例如未计算，不强制凑计算项，但已有回执必须正确。复核旧运行使用当前合同并记录合同哈希，不能冒充旧运行当时已有这道门禁。

验收器检查回答与事件哈希、宿主完成状态、实际命令事件中的路由退出状态和 JSON 结果，以及最终回答的计算回执。只运行 `--help`、仅有退出 0、最后一次路由失败或必需回执缺失都不能放行；合法重试可以恢复。正确的身份阻断可通过机器检查，但 `route.ready=false`，不能解释为研究获准继续。

语义、来源可信度、实际 Skill 加载、路由是否切合问题及所有关键计算是否覆盖，仍需人工审查。每条既定标准保留为 `manual_criteria[].status=PENDING`，包括利润率比较；验收器不靠关键词匹配认证研究内容，始终保持 `research_complete=false`。这是仓库验收入口的门禁，不是对所有宿主聊天输出的自动拦截器。
