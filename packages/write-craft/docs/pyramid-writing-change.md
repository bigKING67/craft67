# 金字塔写作流程与成稿验收

本次实现继续面向工作方案、汇报和决策文档，默认精炼但论证完整。它不增加观点文章、广告或平台操作入口，不改变 Skill 名称、版本或安装位置。

## 行为变化

写作先确定读者的问题与来源支持的回答，再把相关材料归组为判断，检查下层是否支撑上层、同层是否使用一致分类依据、顺序是否有意义。成文时每段增加理由、证据、条件或行动信息；整稿编辑按信息贡献合并重复，最后双向核对来源。短汇报无需造出推荐、理由树或固定章节。

`SKILL.md` 承担四步主流程与必读路由；`decision-documents.md` 说明分组、推理和完整示范；`clear-chinese.md` 说明按意义删改。结构是内容关系，不能用标题数量、压缩比例或固定理由数量验收。

## 旧规则的迁移与保护

| --- | --- | --- |

preserve/propose、来源双向核对、完整初稿、clean/annotated、中文编辑、最多一次额外修订的共享预算仍有效。独立复核发现短任务读取覆盖不足和合成示例混淆交付/启用；两处在候选冻结前修正。原测试中的精确条款断言迁到真实所在参考，并检查入口路由；没有删除这些断言来让测试通过。

## 来源与复用

已完整阅读 ljg-writes 的入口和 WriteEssay 工作流，参考 ljg-paper、ljg-plain 的相关入口。沿用 `upstream-absorption.md` 的固定来源，不引入其个人笔记保存、默认千字文章、Org/Denote 或署名约定。新增内容是独立表述，不复制上游正文或示范。

金字塔方法依据 Barbara Minto 的公开概念说明（2026-09-26，https://www.barbaraminto.com/concept）：从相关事实归组并提炼判断，再向读者逐层展开。未复制书籍、课程或官网文字，也不声称已阅读整本书。无新增 upstream checkout 或运行时依赖。

## 可复现的比较流程

开发脚本 `scripts/eval_writing_sample.py` 接收 `--skill`、`--cases`、`--output-dir`、`--model`、`--judge-model`，分别运行修改前后的冻结 Skill。模型和 thinking 必须相同；默认 low，每份只生成一次，不允许修订或覆盖已有输出目录。每份候选先落盘，再做事实评审；保留摘要、输入、候选、判定和用量，不保存 raw JSONL。连续三个 ERROR 停止，余项记录为未运行。Skill 变化不能取得通过状态。

`evals/pyramid-heldout.json` 含六份独立编写的新合成材料：短汇报、方案说明、决策比较各两份。材料作者未读 Skill、修改文档或旧稿；候选冻结后才用于生成。它们在本轮后成为已见材料，不能继续称为新的盲测集。

比较时给独立评阅者相同来源、请求和匿名 A/B 稿，不提供 Skill、预期答案或版本映射。逐份判断中心回答、纵向支撑、同层分组、重复和语言自然度，引用具体句段；字数只描述长度，不决定优劣。单独记录事实完整性。这里的匿名比较不是只读成稿的理解测试，更不是真人阅读。

本候选质量门槛：事实回归通过；六组无实质退步，至少四组有可定位的结构或精炼改善。达不到时记录失败，不能把机器合同 PASS 或更短字数当成写作质量通过。若再次修改，需冻结新候选并换未参与调试的材料复验，不选择性重跑同一份直到好看。旧状态和发布策略不改，比较记录不改写历史 PASS。

## 验收层次

- 静态/单元/打包：验证引用、合同、开发工具与包边界。
- 事实与交付回归：现有回归加上纵向支撑和同层分组生成案例。
- 评审器校准：增加四组正反例，覆盖结论前置但理由无关、同层混类、标题重复、正文与表格重复。
- 写作比较：六份首稿匿名配对，并保留具体缺陷与分歧。
- 真人验收：沿用至少三份真实脱敏文档与独立阅读记录要求；合成材料和模型比较均不替代它。

结果与当前证据见本轮 `.artifacts/write-craft-evals/pyramid-r42/` 和文末结果记录。安装、commit、push、版本变更及发布不在本次实施内。

本轮不降低 `source-integrity.md` 的必读要求（r53 显示其来源边界确有作用），改为补充写法：`SKILL.md` 新增“Say what is true, once”，要求边界只写一次、仅在可能误读时使用对照否定、将来源免责句改写为肯定条件而非照抄或删除、编辑过程说明直接删去而不改写成工作现状；`clear-chinese.md` 增加合成的防御稿与改写稿对照，删除与前文重复的“Language and precision”一节。新增开发工具 `scripts/style_metrics.py`，只描述对照否定密度与跨段重复片段，不作为验收判据。

验证：主代理在规则修改后自拟一份长篇虚构合同审阅材料，每臂每模型各生成一次、零修订。对照否定数量旧版 → 最终候选为 DeepSeek Flash 7 → 3、GPT-5.5 6 → 5、Claude Sonnet 5 11 → 6。DeepSeek 事实评审两版均 PASS；GPT 旧版 FAIL（漏写现状与复用待复核），中间候选 FAIL（删去同类条款需核对的条件），最终候选 PASS。Claude 经 `claude -p` 生成（Pi 的 Anthropic 通道未认证，返回空输出），未跑事实评审；主代理阅读发现其把“本文未同步修改”改写成工作现状、补入“新一批”合同，据此修订的规则晚于该次生成，只有静态验证。九份已见短材料上两版否定数与长度无明显差别，这类材料本身较少出现防御式写法。

结论限于单样本、主代理自拟材料和同一评审模型，不构成未见材料质量门槛或真人验收。工件在本地忽略目录 `plain-r59/`。

评测脚本随后改为：`anthropic/<model>` 或 `claude-code/<model>` 经本机 `claude -p` 生成（在临时目录运行、只开放 Read、输出转换为既有 Pi 事件），结构化工具评审仍需 Pi。用该通道对同一长篇材料补跑 Sonnet，两版读取回执均成功、事实评审均 PASS；对照否定旧版 8、最终候选 5，最终候选另有一处标题与内容不符的编辑意见。仍为单样本。

## 版本定位与采样波动（r62）

为定位 r61 的退步，沿用 r61 六份已冻结材料，补跑三个中间版本：`6833ff5`（加入 README 场景）、`31afd50`（拆分入口）、`749efd4`（吸收去 AI 味规则），并对两端 `f3268b2` 与 0.3.0 各补跑一次。共 30 份，生成与评审配置同 r61，每份一次，零修订，无重试，全部作业结束。`f3268b2` 已包含“Say what is true, once”，因此 r61 对该规则的推测不成立。

事实合同的波动与版本差异相当：同一 `f3268b2` 两次分别为 1/6 与 3/6，0.3.0 两次为 1/6 与 2/6，中间版本为 2/6、3/6、2/6。单次事实合同不能区分版本。

三名独立评阅代理按用例分工（每人两个用例），逐份清点 42 份匿名稿的缺陷；七份稿的标签随机打乱，映射封存。短汇报 14 份无 major；方案说明只有 0.3.0 第一次运行各有一处 major（未定写成已定、材料外日历判断），第二次运行未再出现。冷链比较中，各版本都直接相减记录里的总额，例如“只差 2 万元”；评阅者按 derived 计为 major。根代理复核认为这是本轮分类定义过宽所致：请求禁止的是“估算涨价、残值折算”，不是对原数相减，因此不计为退步。

剔除该类后，各臂 major 为：`f3268b2` 0 与 1，`6833ff5` 1，`31afd50` 1，`749efd4` 0，0.3.0 3 与 1；平均总评分为 4.00、4.00、4.00、3.67、3.83、3.50、3.83。没有任何一次改动稳定引入退步。r61 中“旧版更好 4 份”主要来自单次采样：0.3.0 第一次运行恰好较差。

跨版本稳定存在的缺陷是：请求明说“别自己补”，模型仍按另一标准替读者套算金额。七份晚自习比较稿中有五份如此，`f3268b2` 的第二次运行也在内。这是当前生成模型在所有版本下的倾向，不是某次改动造成的。规则修改应针对这一点，并配真实反例。

方法上的结论：在两臂各一次、六份材料的设置下，“至少 4/6 明确改善”的门槛会被采样波动主导。今后每臂每份至少两次生成，才宜判断改善或退步。本轮未修改运行时 Skill。工件见本地忽略目录 `pyramid-r62/`（`aggregate.json`、`defects-*.json`、`mapping-sealed.json`）。
