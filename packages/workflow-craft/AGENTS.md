# Workflow Craft

- 本包是个人或团队本地的跨宿主工作流 Skill；正式包名为 `workflow-craft`，唯一安装运行时为 `skills/workflow-craft/`，运行时不能导入包外代码。Python 3.11+、Git，标准库优先。
- 核心边界：CNB/Gitea 只读、任务快照、本机预检、Git 检查/显式 worktree 创建、批准命令的验证证据、随分支提交的任务目录（契约/本地执行进度/证据/交接）、按会话绑定的 `task` 生命周期、`resume`/`check`、固定产物安装。禁止隐式发布、提交、推送、合并、部署、模型调用、Agent 启动或常驻服务。
- 产品目标是可独立承担个人与团队开发流程，在真实项目证明能力承接和收益后替代 Trellis；验收与阶段边界见 [退役方案](docs/trellis-retirement.md)。0.5.0 已有最小本地任务树/生命周期与会话绑定；完整团队、宿主和 AIOS 迁移验收尚未完成。不内置文件系统隔离引擎、Sandbox、远程执行或宿主工具重定向；并行尝试复用 Git 分支、clone 和 worktree。新增运行时依赖前须说明现有能力为何无法满足，并先在独立实验包评估，不进入成员安装产物。LayerFS 等文件状态引擎属于 Agent 基础设施，已评估并放弃，不再引入。
- 是否启用持久任务循环取决于接续/交接需求，不取决于文件数量；复用已有项目流程。L0 不创建任务或文档；复杂度和风险独立。在显式切换前，已有 Trellis 托管流程只接工具，不接管生命周期，不写 Trellis 文件。任务目录派生自平台任务或项目本地契约；execution 仅记录本地执行，不复制平台分配/审批/合并状态。历史完成与当前依据是否有效分别报告，结束会话不能等于完成任务。提交进仓库的内容不得含本地绝对路径、remote、命令输出或凭据。
- 首次正式接入须明确选择项目模式，不默选；已有模式复用。模式切换保留任务、身份、检查、历史证据及既有任务的集成/平台要求，旧通过因策略变化失效。个人本地任务不要求平台账号或邮箱，不将本地就绪解释成平台认证或合并授权。
- 不加工作流 Hook、每轮 prompt 注入、子代理编排或个人 journal；会话接续靠显式 `resume`。可选宿主 UI 适配器仅只读显示项目模式，不执行检查、不修改任务、不注入模型上下文，不默认安装或覆盖现有状态栏。
- Git 检查覆盖整个实际 Git 根，包括其他包 WIP。不得 stash、reset、clean、覆盖现有工作区。工作树不是服务/数据库沙箱。
- 项目自行决定集成方式；当前 human-serialized 配置仅限定工具的本地交接检查，不接管项目合并队列/CI，也不能认证它们。
- 证据过期不等于立即重跑：按当前任务和项目门禁选择验证时机与范围，不为固定流程重复执行；未验证不能据此声称通过。未运行、依赖缺失、超时、取消、代码/策略漂移都不算通过。证据绑定代码内容哈希、base、契约版本、命令、策略和退出码；本地哈希不构成可信执行证明或合并授权。
- 凭据仅从显式配置的环境变量读取，不放 URL/配置/日志；禁打印响应体与原始 HTTP 错误。HTTP 重定向不得携带凭据跨域。验证子进程会执行项目代码，必须明确批准，不称只读。
- 外层 scripts 只负责开发、验收、打包、安装；Trellis 盘点是只读开发工具，不进入成员安装产物，不等于导入或接管。安装仅写显式目标，拒绝覆盖未知/漂移副本，不改全局宿主配置或账号。
- 门禁：`python3 scripts/check.py`。测试用临时 Git 仓库和本地模拟 HTTP，不接真实公司平台，不调用付费模型。源码、离线合同、安装一致性、宿主加载、live 和远端发布分别报告。
