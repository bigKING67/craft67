# 项目数据目录

新项目初始化到 `.workflow/`。配置、版本锁、任务契约、验证摘要及交接随项目提交；`local/` 仍只存忽略的会话绑定、快照与原始执行输出。Codex/Pi 的 `.agents/skills/workflow-craft` 和 Claude 的 `.claude/skills/workflow-craft` 是宿主入口，不是业务项目目录。工具维护源在自己的包内，项目不复制另一套编码规则或规格树；`AGENTS.md`、`CLAUDE.md` 和既有业务文档仍是权威。

已有 `.team-workflow/` 的项目按原目录继续工作，不因升级全局 Skill 自动迁移或升级项目。需要迁移时：

1. 先按固定产物安装说明显式升级该项目的宿主副本，并核对/更新项目版本锁。停止旧版会话写入；不要混用两个版本写任务。
2. 从当前项目副本运行 `twc.py --project . migrate`，只读预览目录清单的 `inventory_sha256`，核对需要更新的外部脚本、规则引用和注册检查 argv。
3. 用户授权覆盖后，运行 `twc.py --project . migrate --apply --approved-inventory <inventory_sha256>`。工具只重命名数据目录，不改文件内容、不提交、不修改宿主规则、也不合并业务目录。清单变化则拒绝，重新核对后再预览。
4. 按项目规范同步外部入口、路径保护、忽略规则和检查命令。旧记录中的 `.team-workflow/` 引用在新目录中仍可读取，保留原始字节与哈希；不要批量替换历史证据、作者或旧合同。
5. 运行 `doctor --local`、`check` 和有关任务的 `resume`。目录路径、运行时或项目规则变化可能使证据过期；只在所需验证时点重验受影响检查，不手改历史哈希，也不把迁移成功当业务验收通过。

两套数据目录同时存在时拒绝选路，不双写、不自动合并。已有无效/外部工具配置、链接或重解析点、已跟踪的本地输出、被 Git 忽略的目标配置、清单漂移以及在途写入均不能越过迁移。一次目录重命名失败时保留旧目录，可核对后重试；迁移成功后再次执行返回无需变更。不使用软链接，原生 Windows 的状态栏和入口沿用同一解析器。

回退需先停止写入并核对新目录自迁移后有无新增内容，再显式将整个目录改回旧名，同时恢复对应的项目固定版本、路径入口及规则。保留已产生的历史和新证据；旧版运行时不能用于写入它不匹配的版本锁。不自动清理独立 worktree，不把项目数据目录当成 Git worktree 或部署目录。
