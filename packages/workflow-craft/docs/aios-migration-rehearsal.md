## 接续与入口

- 全部 384 条任务建立只读映射，保留源路径、id、目录名、状态、归档位置、profile、字段名、父子关系和原始文件。没有批量转换所有活跃任务。
- 只为一个实际父任务及三个子任务建立 Workflow Craft 接续记录。父任务保留 planning，三个子任务保留 in_progress；契约直接引用原 PRD 和验证文件。原有未完成业务验收仍需复核，不复制完整需求、不继承旧人的身份、不复制旧宿主 session，也不生成平台批准。
- Codex、Claude、Pi 的旧发现入口、Hook、Trellis runtime 移到副本内档案。原 `.trellis/tasks` 与 `.trellis/spec` 保持原位、只读。根 AGENTS 仅加入限定演练范围的例外，Claude 保留根规则导入和宿主规则映射；其他项目约束按字节保护。这个例外不是可直接用于正式项目的完整路由改写。
- Claude 的部分旧 Skill、Agent、Hook 只存在于本机并被 Git 忽略。普通 clone 无法代表这些入口，本轮显式冻结了实际文件后才演练停用。非 Trellis 的两个内部 Skill 链接保留。
- 两个固定入口为 `.agents/skills/workflow-craft` 和 `.claude/skills/workflow-craft`，项目配置为 schema 2、team、`workflow_owner=workflow-craft`。原 schema 1 配置和旧运行时保留在档案，不延续其平台连接或账号配置到这个离线副本。

原项目的 `workflow_owner=trellis` 是既有“生命周期由 Trellis 管理、TWC 提供工具”的协作方式，不是已经发生双重写入的证明。独立接管时必须明确切换所有者并处理旧入口；只升级安装包不会完成这一转换。

回退结果只证明这份冻结副本的成功往返，不证明通用迁移器具备事务、并发冲突或任意中断恢复能力。接收副本的 Claude CLI 调用属于同机确定性检验，不是新的 Claude 原生模型会话或真人接手。

独立复核发现：最初接收副本在完成拒绝测试中已实际启动父任务，因而它不再满足“保持来源 planning 状态”的守护。该副本保留为负向样本；另建干净接收副本完成最终只读接续和守护验证，不把负向测试前的快照冒充接收端最终状态。

首次准备时出现的失败保留：生成缓存不应加入共享 Git 快照；旧配置目录存在时 init 拒绝覆盖；演练暂存错误纳入本地绑定时，运行时拒绝继续写任务。随后在隔离副本中纠正来源分类、显式归档旧配置、从共享索引移除本地绑定，没有放宽运行时保护或改写历史证据。该仓库是本地实验材料，不直接作为对同事发布的安装包。
