# Trellis 替代与退役验收

目标：Workflow Craft 独立支撑个人开发和多人协作，在 AIOS 的实际任务上证明能力不退步、流程收益可观察，然后退役项目中的 Trellis。正式名称仍为 `workflow-craft`。

**当前结论：尚不具备 AIOS 退役条件。** v0.5.0 源码增加最小本地任务树、生命周期与会话绑定；AIOS 尚未迁移，独立成员和完整团队接管未验收。“无需安装 Trellis 即可使用”不等于“已经替代 AIOS 中定制过的 Trellis”。项目业务规则和部署配置仍由项目维护。

## 当前基线

2026-10-30 对 AIOS 本地工作树的只读盘点：Trellis 版本文件为 0.6.15；382 个任务记录，50 个未归档、332 个已归档，35 个 spec 文件，36 条有向父子引用全部可解析。这里的引用数量包括 parent 和 children 两个方向，不是 36 个独立父子对。

- 未归档任务：5 个 planning、44 个 in_progress、1 个 completed。完成与归档是两件事，不自动替项目清理。
- 176 个归档任务缺少 workflow_profile。AIOS 现有读取逻辑将其解释为 full；盘点保留缺省事实，不回写历史。
- 父子引用保存目录名，未必等于 task.json 的 id。任务归档还可能清除活跃子任务的 parent，必须区别历史关联与当前执行关系。
- 现有配置的流程所有者仍是 Trellis，项目锁与两个已检查安装入口仍是旧名 0.2.0。Workflow Craft 源码升级不代表 AIOS 已升级。
- 当前 origin 的主机为 GitHub，工具配置登记 CNB。两者不能被当作已经核对一致的平台身份；真实协作平台与审批来源需要在试点前明确。现有运行时只有 CNB/Gitea 只读 provider，不宣称已经支持 GitHub 的平台审查。
- AIOS 有定制的 Codex/Claude Hook、Pi 扩展和引用 Trellis 路径的仓库门禁。替换这些入口必须保留其行为约束，不能靠删除门禁获得通过。

这些数值是日期化观察，不是迁移常量。正式迁移前重新盘点并绑定冻结的 Git 基线、允许保留的未提交内容和来源哈希。源文件哈希不能证明任务曾经关联哪个代码提交。

## 规则和状态只保留一个权威来源

1. 项目 AGENTS.md、CLAUDE.md、规格和 CI 继续维护项目约束。Skill 引用它们，只保存任务需要的指针与缺口，不另抄一套业务规则。冲突按宿主指令优先级处理，不能声称 Skill 总是优先。
2. 未接平台的任务以项目中的版本化任务契约为权威；接入平台的团队任务以明确绑定的 Issue/分配为权威。本地只记录执行进度和证据，不复制第二份平台负责人、审批或合并状态。平台不可用时报告未知，不把缓存当实时授权。
3. solo/team 是项目协作方式，风险等级独立。一个人做高风险改动仍需相应验证；切回 solo 不抹除既有团队任务的审批和集成要求。
4. 首次只需称呼，不为使用工作流索要邮箱。实际 Git 提交身份、平台账号与权限仍按操作核对；称呼不等于认证身份。
5. 每个任务只有一个执行流程所有者。试点在隔离副本内切换；正式项目切换前仍由 Trellis 管理。切换后旧记录可供追溯，旧 Hook、入口、当前任务指针不能继续写同一任务。
6. 继续采用普通分支、clone、worktree；端口、服务、数据库和缓存需要独立命名空间，worktree 不提供这些隔离。无需引入 Agent 进程管理器、沙箱引擎或常驻工作流服务。

## 数据承接合同

| Trellis 来源 | 承接原则 |
| --- | --- |
| task.json 的 id、原路径和目录名 | 分别保存，引用解析采用真实来源语义；重名或歧义停止该批迁移，不能猜选第一个 |
| parent、children、历史 subtasks | 父子双向核对；旧 subtasks 先确认语义，不能直接改名为 children；归档造成的历史关系保留来源 |
| status 与 archive 路径 | 分别映射执行状态与归档状态；已完成未归档保留；不根据目录位置重新判断业务验收通过 |
| workflow_profile | 保留显式值及缺省来源；旧 full 默认只描述历史读取行为，不成为所有新任务的默认复杂度 |
| prd/design/implement 与上下文清单 | 引用原规格，不复制两套计划；按需迁移有效索引，检查实际消费入口 |
| spec 与项目规则 | 规则继续由项目拥有；保留可解析引用和内容一致性，完成语义等价核对后才替换旧路径 |
| 历史验证、交接与 journal | 保留可追溯来源，历史记录不升级成当前执行证明；journal 作为档案，不要求继续维护个人日记 |
| 本地会话、宿主绑定、运行环境 | 不作为共享任务导入，不复制凭据或绝对路径；接手者从自己会话重新建立绑定 |

后续迁移器先生成只读映射清单，检查未知字段、所有需要保留的附件、引用、冲突与来源哈希；本轮盘点不能替代该清单。真正 apply 前核对冻结输入及批准范围，并提供可恢复的原始清单和数据。按一个明确切换边界完成写入；失败回退，发现并发变化拒绝覆盖。切换后新增的任务与证据须先保存并转换或明确交接，不能用旧快照覆盖新工作来“回滚”。

## 分阶段完成条件

| 阶段 | 交付 | 退出条件 |
| --- | --- | --- |
| M0：事实与验收基线 | 本方案、只读盘点脚本、回归测试、真实 AIOS 摘要 | 任务、关系和规则来源可核对；明确未覆盖项；AIOS 未被写入 |
| M1：独立任务循环 | 最小任务树/生命周期、按会话和工作区接续、按需上下文 | 单人从任务到验证、接续、完成走通；不能假完成、重复建计划、串会话或丢历史 |
| M2：团队闭环 | 责任来源、分工、独立工作区、交接、评审与集成 | 两个成员的隔离执行和交接走通；各自通过但组合失败时准确阻止完成，修复后重验 |
| M3：项目与宿主接管 | 可预览的迁移、规则/入口/CI 等价替换、选定宿主真实试点 | 隔离 AIOS 副本可完全不调用 Trellis；全局启用和项目锁的版本优先级明确，不重复加载 |
| M4：比较与退役 | 对照结果、真人协作结果、切换及回滚演练、最终变更清单 | 能力无关键缺失，收益达标；正式切换和清理分别核对明确授权后实施 |

M0 已完成；0.5.0 源码已实现 M1 的最小任务树、生命周期与会话绑定，新增 15 项定向回归通过。[AIOS 隔离试点](aios-pilot.md) 已推进 M1/M2：冻结的真实源码与 9 项现有测试通过，模拟成员独立 worktree 交接、部分完成和失败集成的阻止通过；0.5.1 修复试点发现的跨 clone 基线解析缺陷，固定安装升级与全新 clone 接续通过。完整业务改动、真人团队及 M3/M4 仍未验收，不能把回放当成实际接管或超过 Trellis。

2026-10-31 开始 M3 的 Codex 隔离试点：保留旧跨宿主门禁，另建限定任务范围的项目门禁；原生目录核对发现项目配置加载不等于旧 Skill 实际停用。当前验证需要受控进程配置，正常项目自动接管仍未通过。首个原生样本因登录 Shell 选错 Python 而业务测试失败，失败记录保留；具体环境修正与复验见同一试点记录。

修正验证解释器后，第二轮 Codex 原生会话在同一模型和 300 秒限制内完成该任务的接续、两项验证、完成、交接及结束会话，且没有越界写入；临时信任已恢复。这是 M3 的受控宿主子项通过，仍不满足整个 M3/M4 的退出条件。

后续 [Codex 入口归档与回退试点](aios-codex-entry.md) 将 12 个旧 Skill 和 3 个 Agent 定义移出发现路径，保留逐文件档案与原门禁；指定任务已在无 Skill 禁用覆盖参数的原生会话完成，并由子目录新会话只读接手。入口回退保留新增任务记录，旧证据的 stale/current 随实际内容变化正确切换；宿主自动写入的临时信任已恢复。这补齐 M3 的指定 Codex 入口子项，完整项目迁移、其他宿主、真人协作与对照仍未完成。

[持久试用](aios-l1-handoff.md) 随后完成局部来源质检修复、L0 无任务分流、诊断中断后的恢复，以及限定诊断阶段的主动交接复验。首次超时和后续成功分别保留；命令输出量没有下降，不据此宣称成本改善。真人接手材料已准备但尚未执行；固定 0.5.1 的这些结果不代表当前源码版本或整个 M3/M4 已通过。

0.5.0 完整门禁已通过 190 项测试，独立 Agent 在固定安装的临时项目完成父子任务、暂停、换会话接续与组合代码变更后的重验。最后一次仅接续提示的修订另做固定安装 CLI 回归；版本、产物哈希、首次障碍和验证边界见 [候选验收](compatibility.md#050-lifecycle-candidate-acceptance-2026-10-30)。这些结果推进了 M1，不替代真实 AIOS 或真人团队验收。

首个结构试点已选 AIOS 中一个真实父任务和三个子任务：保留各自 planning/in_progress 状态、已有计划、引用与验证文档，先验证映射和接续。任务的业务细节和完整盘点留在受控项目/本地证据中，不放进通用 Skill。结构回放通过不算真实功能完成。编码对照应选择冻结基线和明确验收的小任务，再覆盖跨会话与团队组合任务；不可修改正在使用的那份 AIOS 工作树制造试点条件。

## 必测场景

| 场景 | 必须观察到的结果 |
| --- | --- |
| 首次进入两个项目，再从子目录或新会话进入 | 每项目只在未选择时询问；名字可复用；模式沿用且可显式更改；只读提问不初始化 |
| 项目已有 AGENTS/CLAUDE、验证脚本和合并队列 | 按项目规则执行；不复制或覆盖规则，不增设无必要的审批与全量测试 |
| 父任务与三个子任务，只有两个验收完成 | 父任务保持未完成；其余任务的完成事实保留，不由会话结束或提交动作代替验收 |
| 同项目两个宿主会话、换分支、切 worktree、上下文中断 | 当前任务不互相覆盖；接手能定位目标、范围、证据与下一步；恢复不自动重复执行已有操作 |
| 代码或接口改变，旧记录仍显示曾经通过 | 当前判断为过期；部分检查通过不掩盖其余过期项；失败、超时、取消、缺依赖不算完成 |
| 两个开发者各自实现，再交换任务 | 称呼、实际提交身份、平台责任分别可追溯；不依赖对方本地目录或聊天记录；提交范围不混入他人 WIP |
| 两边检查各自通过，但组合后接口不兼容 | 集成人看到组合失败，任务不能因旧单支证据完成；修复并验证组合结果后再继续 |
| 实现者与评审者分离 | 有实际独立评审证据；第二轮起只复核变更和未解决问题，最多三轮；本地 advisory 不代替审批 |
| 团队任务中途切 solo、网络中断、无权限或平台不一致 | 原任务协作要求保留；未知和无权限可见；不猜身份、不绕过门禁 |
| 迁移前数据变化、重复标识、坏文件、符号链接或中途失败 | 显式拒绝相应输入，不覆盖源数据；回滚后原任务和引用可用 |
| 全局 Skill 与项目固定副本并存 | 采用可解释的单一版本来源，发现漂移；未验证优先级时不得双重注入 |
| 撤销接管 | 保存试点新产物；恢复原入口后能接续任务，旧新流程不会同时写状态 |

真人同事、独立机器、真实账号权限的验收单独记录。一个 Agent 扮演两个人，或同一操作者换两个账号，只能证明对应的合成/账号场景，不能替代真人协作验收。

## 怎样判定“超过”

先通过上表中适用于 AIOS 的全部关键场景，没有未解决的数据丢失、越权、假通过、任务串线或门禁退步。缺少这一项时，减少 token 或命令数不构成优势。

对照在同一模型、宿主版本、代码基线、任务与验收标准下进行；工具版本固定，记录首次失败与返工，不删掉失败样本只比较最终成功。先锁定比较口径，再开始运行，避免事后挑指标：

- 结果质量：必要验收通过率、漏检/假完成、独立评审发现的问题。
- 接手成本：从新会话开始到正确下一步的必要操作、澄清次数、耗时；保留人工等待/网络异常说明。
- 流程开销：工作流附加上下文、重复读取、无必要检查、重复维护的规则/计划文件。宿主不提供 token 数据时标未测，不把字符数写成 token。
- 团队效果：实际接手是否需要口头补课，冲突能否定位，集成人能否据证据判断组合结果。

建议退役收益门槛：同等质量下，接手成本与流程开销两项都出现可复现的改善，团队闭环通过独立成员试用；如只持平，只能宣称替代，不能宣称超过。每类关键场景至少复验一次，以披露的样本说明结论，不泛化成“任何项目都更好”。测试数量、文档长度或状态栏显示均不单独构成胜出证据。

## 本轮只读工具

从本包目录执行：

```sh
python3 -B scripts/trellis_inventory.py --project /path/to/project
python3 -B -m unittest discover -s tests -p test_trellis_inventory.py
```

脚本输出任务元数据、目录关系、规范/计划来源哈希和待核对项；不输出任务正文、人员字段或原始报错，不导入项目代码，不执行项目检查，不联网，不写项目。若需留存，调用方重定向到已有受控证据目录。退出 0 表示盘点范围内未出现阻断项，1 表示需要核对，2 表示显式项目无法读取；所有输出始终带 `migration_ready=false`。

范围只覆盖 task.json、同目录规范计划文件、spec 和少数项目规则文件；单文件上限 1 MiB，超限显式报告。它不是完整档案备份，不扫描会话/凭据，不验证业务功能、历史提交、宿主加载或平台权限。重复读取哈希与文件集合能发现扫描期间的变化，不构成冻结快照或对抗性文件系统隔离。

本轮真实 AIOS 输出状态为 ok，唯一提示为 1 个已完成未归档任务；1660 个来源文件经重复读取核对，Git 状态前后一致。完整报告 SHA-256：`a5efc3ddda78ab63e47c3c3514b0c23839ef7031af5f57140df981afde8ff737`。这只证明盘点范围内没有未解析的任务关系或检测到的读取漂移，不代表已迁移或可以退役。

M0 盘点轮次新增 12 项盘点回归通过；当时完整包门禁通过 175 项测试，版本检查通过。该轮未改 Skill 运行时、成员安装或宿主配置，未提交、推送或发布；这些历史离线结果不计作 M1–M4 的真实工作流验收。0.5.0 的新增运行时与证据按上文单独报告。
