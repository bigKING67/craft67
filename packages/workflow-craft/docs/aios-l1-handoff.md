## 观察结果

| 样本 | 耗时 | 实际结果 |
| --- | --- | --- |
| L0：更新试用说明的回归计数 | 72.89 秒 | 仅改说明，执行相关九例测试和差异检查；未调用 Workflow CLI、创建任务或修改历史任务 |

| L1 诊断阶段复验 | 280.8 秒 | 保留必要失败、写交接、结束绑定；任务仍为 `in_progress`，业务实现未改，达到诊断阶段要求 |

第二会话的通过只覆盖模拟游标上的来源质检行为和选定离线回放；没有真实数据库事务、媒体端到端或生产样本验收。原生工作区沙箱没有允许 Git 写入，父会话随后按授权做本地 scoped commit；不能把父会话提交记为原生会话能力。

诊断复验从原第一会话相同源码基线 `9f7849c77a41c34fc90d7d36284df132fb5f3eb6` 开始，保留同一初始测试、规格、检查配置、固定 Skill、提示字节及 runner。候选 `734a9f0ff39c794eae01bb9276c07a3b354567c4` 只在项目 AGENTS 增加以下收尾约束：

- 获得必要复现后先写现有交接；失败、缺失检查和未满足验收都可以作为交接内容，不必等业务通过。
- 诊断阶段结束时保持任务开放，只结束会话绑定；最终任务完成仍需全部必要验收。
- 优先读取 `resume` 与需要的引用，保留原始失败，用最小诊断样本区分异常类型，避免重复整份输出；不为查询命令选项读取实现内部。

这是单次观察性复验，不是随机对照，也不是对 Trellis 的比较。两个会话自行生成的新增测试不同：首次新增四个测试方法，复验新增一个包含 12 子场景的方法；不能用耗时推导同一测试工作量下的质量或速度提升。复验没有完成整个业务任务。
